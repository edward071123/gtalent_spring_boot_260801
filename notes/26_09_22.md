# GitHub Actions 自動部署 Spring Boot 到 AWS Ubuntu

日期：2026-09-22

專案：`gtalent_spring_boot_260801`

目標：當程式 push 到 GitHub `main` 分支後，自動測試、打包 JAR、上傳到 AWS EC2 Ubuntu、重啟 `gtalent` systemd 服務，並進行健康檢查。

---

## 1. 本文使用的部署架構

```text
push 到 main
      |
      v
GitHub Actions
  1. 啟動 CI 專用 MySQL
  2. 使用 Java 21 + Maven Wrapper 執行測試與打包
  3. 以 SCP 上傳 app.jar.new
      |
      v
AWS EC2 Ubuntu
  4. 備份目前的 app.jar
  5. 換上新版 app.jar
  6. systemctl restart gtalent
  7. 檢查 http://127.0.0.1:8080/page/login
  8. 失敗時自動換回上一版
```

這個流程只上傳編譯完成的 JAR，不會把原始碼、`.env` 或 GitHub 機密上傳到主機。

### 專案對應設定

| 項目 | 設定 |
| --- | --- |
| Java | 21 |
| 建置工具 | Maven Wrapper `./mvnw` |
| JAR 原始檔名 | `target/gtalent_spring_boot_260801-0.0.1-SNAPSHOT.jar` |
| EC2 使用者 | `ubuntu` |
| EC2 專案目錄 | `/home/ubuntu/gtalent_spring_boot_260801` |
| 部署 JAR | `/home/ubuntu/gtalent_spring_boot_260801/target/app.jar` |
| systemd 服務 | `gtalent` |
| 健康檢查 | `http://127.0.0.1:8080/page/login` |

## 2. 事前條件

確認以下項目已完成：

- 程式已上傳到 GitHub，主要分支是 `main`。
- EC2 使用 Ubuntu，並已安裝 Java 21。
- MySQL、Nginx、HTTPS 與正式 `.env` 已按 `notes/26_09_03.md` 完成。
- EC2 內的 `/home/ubuntu/gtalent_spring_boot_260801/.env` 可供正式程式使用。
- GitHub Actions 可連到 EC2 的 SSH port。

在 EC2 確認 Java：

```bash
java -version
```

如果未安裝 Java 21：

```bash
sudo apt update
sudo apt install -y openjdk-21-jdk curl
```

## 3. 在 EC2 準備部署目錄

登入 EC2：

```bash
ssh ubuntu@EC2_PUBLIC_IP
```

建立目錄，並讓 `ubuntu` 可以寫入 JAR：

```bash
sudo install -d -o ubuntu -g ubuntu /home/ubuntu/gtalent_spring_boot_260801/target
```

確認正式 `.env` 存在：

```bash
test -f /home/ubuntu/gtalent_spring_boot_260801/.env && echo ".env exists"
```

`.env` 只放在 EC2，不要加入 Git，也不要放到 GitHub Actions workflow。

---

## 4. 調整 systemd 服務

編輯服務檔：

```bash
sudo nano /etc/systemd/system/gtalent.service
```

內容改為固定啟動 `target/app.jar`：

```ini
[Unit]
Description=Gtalent Spring Boot App
After=network.target mysql.service

[Service]
User=ubuntu
Group=ubuntu
WorkingDirectory=/home/ubuntu/gtalent_spring_boot_260801
ExecStart=/usr/bin/java -jar /home/ubuntu/gtalent_spring_boot_260801/target/app.jar
SuccessExitStatus=143
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

重載設定：

```bash
sudo systemctl daemon-reload
sudo systemctl enable gtalent
```

第一次自動部署前可以先停止舊服務：

```bash
sudo systemctl stop gtalent
```

GitHub Actions 部署帳號必須可在無互動密碼的情況下執行 `sudo systemctl restart gtalent`。AWS Ubuntu 預設的 `ubuntu` 帳號通常已有權限，但仍應先手動測試：

```bash
sudo -n systemctl status gtalent
```

## 5. 建立 GitHub Actions 專用 SSH key
請先參閱26_09_03.md第15項後 再來執行本項目   
先確保C:/aws存在。   
在自己的電腦上建立一組「只給 GitHub Actions 部署用」的 key，不要重用個人 SSH key：
```bash
ssh-keygen -t ed25519 -C "github-actions-gtalent-deploy" -f "C:/aws/gtalent_actions_ed25519"
```

在C:/aws目錄下會產生兩個檔案：

```text
gtalent_actions_ed25519       # 私鑰，放到 GitHub Secret
gtalent_actions_ed25519.pub   # 公鑰，放到 EC2
```

將公鑰加入 EC2。這一步必須用 `-i` 指定「目前已經可以登入 EC2 的舊私鑰」，不是剛建立的 `gtalent_actions_ed25519`：

```bash
cat /path/to/gtalent_actions_ed25519.pub \
  | ssh \
      -i /path/to/existing-ec2-private-key \
      ubuntu@EC2_PUBLIC_IP \
      'umask 077; mkdir -p ~/.ssh; cat >> ~/.ssh/authorized_keys; chmod 700 ~/.ssh; chmod 600 ~/.ssh/authorized_keys'
```

範例：

```bash
cat "C:/aws/gtalent_actions_ed25519.pub" \
  | ssh \
      -i "C:/test/gtalent_ec2_2609" \
      ubuntu@43.213.59.81 \
      'umask 077; mkdir -p ~/.ssh; cat >> ~/.ssh/authorized_keys; chmod 700 ~/.ssh; chmod 600 ~/.ssh/authorized_keys'
```

如果沒有指定舊私鑰，SSH 會在新公鑰尚未寫入前就因無法驗證身分，顯示 `Permission denied (publickey)`。

測試新 key：

```bash
ssh \
  -i "C:/aws/gtalent_actions_ed25519" \
  ubuntu@43.213.59.81
```

測試完成後，取得 EC2 SSH host key：

```bash
ssh-keyscan -H EC2_PUBLIC_IP > ec2_known_hosts
```

`ssh-keyscan` 只是取得 key，不會幫你驗證主機身分。應先用已信任的 EC2 連線或 AWS 主控台核對 fingerprint，再把內容存入 GitHub。

## 6. 建立 GitHub production Environment

進入 GitHub repository：

```text
Settings -> Environments -> New environment -> production
```

建議在 `production` 設定：

- Deployment branches 只允許 `main`。
- 如果 GitHub 方案支援，設定 Required reviewers，讓正式部署前需要手動核准。

### Environment variables

在 `production -> Environment variables` 加入：

| 名稱 | 內容範例 |
| --- | --- |
| `EC2_HOST` | EC2 Elastic IP 或網域 |
| `EC2_USER` | `ubuntu` |

### Environment secrets

在 `production -> Environment secrets` 加入：

| 名稱 | 內容 |
| --- | --- |
| `EC2_SSH_KEY` | `gtalent_actions_ed25519` 私鑰的完整內容 |
| `EC2_KNOWN_HOSTS` | `ec2_known_hosts` 的完整內容 |

也可以用 GitHub CLI 設定：

```bash
gh variable set EC2_HOST --env production --body "EC2_PUBLIC_IP"
gh variable set EC2_USER --env production --body "ubuntu"
gh secret set EC2_SSH_KEY --env production < gtalent_actions_ed25519
gh secret set EC2_KNOWN_HOSTS --env production < ec2_known_hosts
```

不要把私鑰、`.env` 或正式資料庫密碼提交到 Git。

## 7. 建立 GitHub Actions workflow

在專案建立：

```text
.github/workflows/deploy.yml
```

內容：

```yaml
name: Test and deploy to AWS EC2

on:
  push:
    branches:
      - main
  workflow_dispatch:

permissions:
  contents: read

concurrency:
  group: production-deploy
  cancel-in-progress: false

jobs:
  deploy:
    name: Build, test and deploy
    runs-on: ubuntu-latest
    timeout-minutes: 20
    environment: production

    services:
      mysql:
        image: mysql:8.4
        env:
          MYSQL_DATABASE: project26_v1_test
          MYSQL_ROOT_PASSWORD: ci_test_password
        ports:
          - 3306:3306
        options: >-
          --health-cmd="mysqladmin ping -h 127.0.0.1 -pci_test_password"
          --health-interval=10s
          --health-timeout=5s
          --health-retries=10

    steps:
      - name: Checkout source code
        uses: actions/checkout@v7
        with:
          persist-credentials: false

      - name: Set up Java 21
        uses: actions/setup-java@v6
        with:
          distribution: temurin
          java-version: "21"
          cache: maven

      - name: Build and test
        env:
          TEST_DB_NAME: project26_v1_test
          TEST_DB_PORT: "3306"
          TEST_DB_USERNAME: root
          TEST_DB_PASSWORD: ci_test_password
          GMAIL_USERNAME: ci@example.invalid
          GMAIL_PASSWORD: ci-only-password
          JWT_SECRET: ci-only-jwt-secret-must-be-at-least-32-characters
          JWT_ACCESS_TOKEN_SECONDS: "900"
          JWT_REFRESH_TOKEN_SECONDS: "604800"
          APP_BASE_URL: http://localhost:8080
          PASSWORD_RESET_TOKEN_MINUTES: "30"
          NEWEBPAY_MERCHANT_ID: CI_ONLY
          NEWEBPAY_HASH_KEY: 12345678901234567890123456789012
          NEWEBPAY_HASH_IV: "1234567890123456"
          NEWEBPAY_VERSION: "2.0"
          NEWEBPAY_GATEWAY_URL: https://ccore.newebpay.com/MPG/mpg_gateway
          NEWEBPAY_NOTIFY_URL: http://localhost:8080/payments/newebpay/notify
          NEWEBPAY_RETURN_URL: http://localhost:8080/payments/newebpay/return
        run: |
          chmod +x mvnw
          ./mvnw --batch-mode --no-transfer-progress clean package

      - name: Prepare deployment artifact
        run: |
          cp target/gtalent_spring_boot_260801-0.0.1-SNAPSHOT.jar target/app.jar
          test -s target/app.jar

      - name: Configure SSH
        env:
          EC2_SSH_KEY: ${{ secrets.EC2_SSH_KEY }}
          EC2_KNOWN_HOSTS: ${{ secrets.EC2_KNOWN_HOSTS }}
        run: |
          install -d -m 700 ~/.ssh
          printf '%s\n' "$EC2_SSH_KEY" > ~/.ssh/gtalent_deploy
          chmod 600 ~/.ssh/gtalent_deploy
          printf '%s\n' "$EC2_KNOWN_HOSTS" > ~/.ssh/known_hosts
          chmod 600 ~/.ssh/known_hosts

      - name: Upload JAR
        env:
          EC2_HOST: ${{ vars.EC2_HOST }}
          EC2_USER: ${{ vars.EC2_USER }}
        run: |
          test -n "$EC2_HOST"
          test -n "$EC2_USER"
          scp \
            -i ~/.ssh/gtalent_deploy \
            -o BatchMode=yes \
            -o StrictHostKeyChecking=yes \
            -o ConnectTimeout=10 \
            target/app.jar \
            "$EC2_USER@$EC2_HOST:/home/ubuntu/gtalent_spring_boot_260801/target/app.jar.new"

      - name: Activate release and verify
        env:
          EC2_HOST: ${{ vars.EC2_HOST }}
          EC2_USER: ${{ vars.EC2_USER }}
        run: |
          ssh \
            -i ~/.ssh/gtalent_deploy \
            -o BatchMode=yes \
            -o StrictHostKeyChecking=yes \
            -o ConnectTimeout=10 \
            "$EC2_USER@$EC2_HOST" 'bash -se' <<'REMOTE_SCRIPT'
          APP_DIR=/home/ubuntu/gtalent_spring_boot_260801
          CURRENT_JAR="$APP_DIR/target/app.jar"
          BACKUP_JAR="$APP_DIR/target/app.jar.previous"
          INCOMING_JAR="$APP_DIR/target/app.jar.new"

          test -s "$INCOMING_JAR"

          if test -f "$CURRENT_JAR"; then
            cp "$CURRENT_JAR" "$BACKUP_JAR"
          fi

          mv "$INCOMING_JAR" "$CURRENT_JAR"
          sudo systemctl restart gtalent

          for attempt in $(seq 1 30); do
            if curl --fail --silent --show-error \
              http://127.0.0.1:8080/page/login > /dev/null; then
              echo "Deployment succeeded."
              exit 0
            fi
            sleep 2
          done

          echo "Health check failed."
          sudo journalctl -u gtalent -n 80 --no-pager || true

          if test -f "$BACKUP_JAR"; then
            echo "Rolling back to the previous JAR."
            mv "$BACKUP_JAR" "$CURRENT_JAR"
            sudo systemctl restart gtalent
          else
            echo "No previous JAR is available for rollback."
          fi

          exit 1
          REMOTE_SCRIPT
```

### Workflow 做了什麼

1. `push` 到 `main` 或在 GitHub 手動執行時觸發。
2. 在 GitHub runner 啟動 MySQL 8.4 service container。
3. 用 Java 21 執行專案測試與打包。
4. 只有建置成功才會連線 EC2。
5. JAR 先上傳為 `app.jar.new`，避免上傳一半就被啟動。
6. EC2 先把現行版備份為 `app.jar.previous`，再替換新版。
7. 新版啟動後，最多等待 60 秒檢查登入頁面。
8. 健康檢查失敗時顯示最後 80 行 log，並自動恢復上一版 JAR。

## 9. 手動回滾

成功部署後，上一版會保留在：

```text
/home/ubuntu/gtalent_spring_boot_260801/target/app.jar.previous
```

如果上線後才發現問題，可在 EC2 手動回滾：

```bash
cd /home/ubuntu/gtalent_spring_boot_260801/target
test -f app.jar.previous
cp app.jar app.jar.failed
mv app.jar.previous app.jar
sudo systemctl restart gtalent
sudo systemctl status gtalent
```

回滾 JAR 只能恢復程式。如果新版 Flyway migration 已修改資料庫，必須另外確認舊版程式與新資料表結構是否相容。正式 migration 應優先使用向後相容的欄位與資料變更。

## 10. AWS Security Group 與 SSH 安全

這份基礎流程使用 SSH/SCP，所以 GitHub runner 必須能連到 EC2 TCP 22。

GitHub-hosted runner 的公開 IP 不是單一固定 IP，因此不應為了方便而長期將 SSH `22` 開放為 `0.0.0.0/0`。AWS 也建議 SSH 不要對全世界開放。

正式環境建議依安全需求改用以下任一方案：

1. 在 AWS VPC 內使用自建 GitHub Actions runner，Security Group 只允許 runner 連入 EC2。
2. 使用 GitHub OIDC 取得短效 AWS 權限，再用 AWS Systems Manager Run Command 部署，完全不開放 SSH port。
3. 透過具有固定出口 IP 的受控 runner 或跳板主機部署。

其他安全注意事項：

- SSH 只允許 key 登入，關閉密碼登入。
- 部署 key 只用於這個專案，定期更換。
- 使用 GitHub `production` Environment 保護正式 secrets。
- Workflow 只授權 `contents: read`。
- 不要在 Actions log 中 `echo` 私鑰或其他 secrets。
- 正式專案可將 `actions/checkout` 與 `actions/setup-java` 從版本 tag 改為完整 commit SHA，降低 action 供應鏈被替換的風險。

## 11. 常見問題

### Actions 顯示 `Connection timed out`

原因通常是 EC2 Security Group、NACL、主機防火牆或 EC2 沒有公開連線路徑。確認 GitHub runner 的連線方案可到達 TCP 22。

### Actions 顯示 `Host key verification failed`

重新在可信任的網路上取得並核對 EC2 host key，再更新 `EC2_KNOWN_HOSTS`。如果 EC2 曾重建，host key 通常會變更。

### Actions 顯示 `Permission denied (publickey)`

檢查：

```bash
chmod 700 ~/.ssh
chmod 600 ~/.ssh/authorized_keys
```

並確認 GitHub `EC2_SSH_KEY` 是私鑰，EC2 `authorized_keys` 放的是對應公鑰。

### `scp` 顯示 `Permission denied`

檢查 target 目錄所有者：

```bash
ls -ld /home/ubuntu/gtalent_spring_boot_260801/target
sudo chown ubuntu:ubuntu /home/ubuntu/gtalent_spring_boot_260801/target
```

### Maven 測試連不到 MySQL

確認 workflow 的 MySQL service 已通過 health check，並且 `TEST_DB_NAME`、`TEST_DB_PORT`、`TEST_DB_USERNAME` 與 `TEST_DB_PASSWORD` 和 service 設定一致。

### systemd 無法啟動

在 EC2 查看：

```bash
sudo systemctl status gtalent
sudo journalctl -u gtalent -n 200 --no-pager
```

常見原因包含 Java 版本不對、`.env` 缺少設定、MySQL 連線失敗、Flyway migration 失敗或 8080 port 已被佔用。
