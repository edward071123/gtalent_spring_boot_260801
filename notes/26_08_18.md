# 2026-08-18 API 呼叫後程式流程

## 1. 會員註冊 `POST /members/register`

1. Request 進到 `MemberController.register()`。
2. Spring 先用 `@Valid` 檢查 `MemberRegisterRequest`：
   - `name` 必填，最多 30 字。
   - `gender` 必填，只能是 0、1、2。
   - `account` 必填，最多 30 字。
   - `email` 格式正確，最多 128 字。
   - `password` 必填，長度 6 到 12。
   - `confirmPassword` 必填。
3. 驗證成功後，controller 呼叫 `MemberService.register()`。
4. Service 先檢查 `password` 和 `confirmPassword` 是否一致。
5. Service 用 `MemberRepository.countByAccount()` 查 `members` table，確認 account 沒重複。
6. Service 用 `PasswordEncoder.encode()` 將密碼加密成 BCrypt 字串。
7. Service 建立 `Member` entity，呼叫 `repository.save(member)` 寫入 DB。
8. `Member.prePersist()` 自動設定 `created_at` 和 `updated_at`。
9. Controller 回傳 `會員註冊成功`。

## 2. 會員登入 `POST /members/login`

1. Request 進到 `MemberController.login()`。
2. Spring 用 `@Valid` 檢查 `MemberLoginRequest`：
   - `account` 必填。
   - `password` 必填。
3. Controller 呼叫 `MemberService.login()`。
4. Service 用 `MemberRepository.findOneByAccountAndStatus()` 查詢狀態為 1 的會員。
5. 找不到會員時，丟 `MemberAccountExcption`，回傳帳號或密碼錯誤。
6. 找到會員後，用 `PasswordEncoder.matches()` 比對明文密碼和 DB 的 BCrypt 密碼。
7. 密碼正確後，Service 呼叫 `createAndSaveToken()`。
8. `JwtService` 產生兩顆 JWT：
   - `accessToken`
   - `refreshToken`
9. Service 將兩顆 token 的 hash、owner type、owner id、過期時間存入 `auth_tokens` table。
10. Controller 回傳 `TokenResponse`，內容包含雙令牌：
    - `tokenType`
    - `accessToken`
    - `refreshToken`
    - `accessExpiresAt`
    - `refreshExpiresAt`

## 3. 呼叫需要登入的會員 API

受保護 API 目前包含：

```http
GET /members/{id}
PUT /members/{id}/profile
PUT /members/{id}/password
DELETE /members/{id}
```

呼叫時 header 要帶：

```http
Authorization: Bearer accessToken
```

如果 access token 已過期，但 refresh token 還有效，還要同時帶：

```http
X-Refresh-Token: refreshToken
```

流程：

1. Request 先進到 `WebConfig` 註冊的 `AuthInterceptor`。
2. `AuthInterceptor.preHandle()` 從 `Authorization` 讀取 access token。
3. `JwtService.parse()` 驗證 JWT 簽章和過期時間。
4. access token 有效時，`AuthInterceptor` 檢查：
   - `ownerType` 必須是 `MEMBER`。
   - `tokenType` 必須是 `access`。
   - token hash 必須存在於 `auth_tokens`。
   - token 不能被 revoked。
   - token 在 DB 中的 `access_expires_at` 不能過期。
5. 如果 API 路徑是 `/members/{id}`，會確認 token 裡的 member id 等於 path id。
6. 檢查通過後才進入 `MemberController`。
7. Controller 呼叫 `MemberService` 做實際業務邏輯。

## 4. Access Token 過期時的自動 Refresh

1. Request 一樣先進 `AuthInterceptor`。
2. `JwtService.parse(accessToken)` 發現 access token 過期，丟 `ExpiredJwtException`。
3. Interceptor 從 `X-Refresh-Token` 讀取 refresh token。
4. Interceptor 驗證 refresh token：
   - JWT 簽章正確。
   - refresh token 尚未過期。
   - `ownerType` 是 `MEMBER`。
   - `tokenType` 是 `refresh`。
   - refresh token 的 owner id 要等於過期 access token 的 owner id。
5. Interceptor 用 refresh token hash 查 `auth_tokens`。
6. 如果 refresh token 對應的 DB 紀錄存在、未 revoked、未過期，代表可以換 token。
7. Interceptor 將舊 token 紀錄設成：
   - `revoked = 1`
   - `deleted_at = now`
8. Interceptor 產生新 access token 和新 refresh token。
9. 新 token hash 寫入 `auth_tokens`。
10. Request 繼續進 controller，原本 API 仍會執行。
11. 新 token 會放在 response header：

```http
X-New-Access-Token: 新 accessToken
X-New-Refresh-Token: 新 refreshToken
X-New-Access-Expires-At: access 過期時間
X-New-Refresh-Expires-At: refresh 過期時間
```

前端收到這些 header 後，要更新本地保存的雙令牌。

## 5. 手動 Refresh `POST /members/refresh`

Request body：

```json
{
  "refreshToken": "refreshToken"
}
```

流程：

1. Request 進到 `MemberController.refresh()`。
2. Controller 呼叫 `MemberService.refresh(refreshToken)`。
3. Service 驗證 refresh token 是否為合法 JWT。
4. Service 檢查 `ownerType = MEMBER`、`tokenType = refresh`。
5. Service 用 refresh token hash 查 `auth_tokens`。
6. 如果 token 不存在、已 revoked、已刪除，回傳 token 不合法。
7. 如果 `refresh_expires_at` 已過期，將該筆 token 設成 revoked，回傳 token 已過期。
8. 如果 refresh token 有效，撤銷舊紀錄，發新 access token 和 refresh token。
9. 新 token hash 寫入 `auth_tokens`。
10. Controller 回傳新的 `TokenResponse`。

## 6. 登出 `POST /members/logout`

Request body：

```json
{
  "refreshToken": "refreshToken"
}
```

流程：

1. Request 進到 `MemberController.logout()`。
2. Controller 呼叫 `MemberService.logout(refreshToken)`。
3. Service 用 refresh token hash 查 `auth_tokens`。
4. 找到有效紀錄時，將該筆 token 設成：
   - `revoked = 1`
   - `deleted_at = now`
5. Controller 回傳 `會員登出成功`。
6. 之後同一組 token 不能再 refresh 或通過受保護 API 檢查。

## 7. 修改基本資料 `PUT /members/{id}/profile`

Request body 可只帶要修改的欄位：

```json
{
  "name": "Edward",
  "gender": 1,
  "email": "edward@example.com"
}
```

流程：

1. Request 先經過 `AuthInterceptor` 驗證 access token。
2. 通過後進 `MemberController.updateProfile()`。
3. Spring 用 `@Valid` 檢查有帶的欄位格式。
4. Controller 呼叫 `MemberService.updateProfile()`。
5. Service 查詢狀態為 1 的 member。
6. `name`、`gender`、`email` 有帶才更新，沒帶就保留原值。
7. Entity 變更在 transaction 結束時由 JPA 寫回 DB。
8. `Member.preUpdate()` 自動更新 `updated_at`。

## 8. 修改密碼 `PUT /members/{id}/password`

Request body：

```json
{
  "password": "abc12345",
  "confirmPassword": "abc12345"
}
```

流程：

1. Request 先經過 `AuthInterceptor` 驗證 access token。
2. 通過後進 `MemberController.updatePassword()`。
3. Spring 用 `@Valid` 檢查密碼長度和確認密碼必填。
4. Controller 呼叫 `MemberService.updatePassword()`。
5. Service 檢查 `password` 和 `confirmPassword` 是否一致。
6. Service 查詢狀態為 1 的 member。
7. Service 用 `PasswordEncoder.encode()` 產生新的 BCrypt 密碼。
8. Entity 變更在 transaction 結束時由 JPA 寫回 DB。

## 9. 刪除帳號 `DELETE /members/{id}`

流程：

1. Request 先經過 `AuthInterceptor` 驗證 access token。
2. 通過後進 `MemberController.delete()`。
3. Controller 呼叫 `MemberService.delete()`。
4. Service 查詢狀態為 1 的 member。
5. Service 做軟刪除：
   - `status = 0`
   - `deleted_at = now`
   - `account = del_yyyyMMddHHmmss_原account`
6. 改 account 是為了釋放原本的 unique account，讓之後可以重新註冊同帳號。
