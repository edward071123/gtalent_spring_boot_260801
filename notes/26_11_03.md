# EC2 改用 Docker 執行 Spring Boot

目前狀況：Docker 已安裝，MySQL 容器名稱是 `docker_mysql`，GitHub Actions 會編譯並上傳 `app.jar`。自己的電腦仍可用原生 Java 和 Maven 開發。

以下命令在 **EC2** 執行。第一次切換會短暫停止網站，建議先確認資料庫已有備份。先暫停 GitHub Actions 的部署 workflow，避免切換時舊版 workflow 重新啟動 systemd 服務；完成第 8 步後再恢復。

## 第一步：停止原本的 gtalent 服務

```bash
sudo systemctl stop gtalent
sudo systemctl disable gtalent
sudo systemctl status gtalent --no-pager
```

`disable` 避免 EC2 重新開機時，舊服務與 Docker 搶占 8080 port。保留原本的 systemd 設定，之後需要時可以回復。

## 第二步：確認 Docker 已安裝

```bash
docker --version
docker compose version
docker ps
```

清單中應看到 MySQL 容器 `docker_mysql`。本次 Compose 使用 `env_file.format: raw`，需要 Docker Compose 2.30.0 以上。部署帳號必須有 Docker 操作權限。

## 第三步：準備放 JAR 的資料夾

沿用目前專案的目錄，並建立 `target`：

```bash
mkdir -p /home/ubuntu/gtalent_spring_boot_260801/target
cd /home/ubuntu/gtalent_spring_boot_260801
```

GitHub Actions 之後會把 JAR 送到：

```text
/home/ubuntu/gtalent_spring_boot_260801/target/app.jar
```

原本 systemd 如果已經在使用這個檔案，可以先用現有 JAR 啟動 Docker；先確認檔案存在：

```bash
ls -lh target/app.jar
```

如果檔案不存在，需要先準備一份已編譯的 JAR，才能第一次手動啟動並驗證。

## 第四步：在資料夾內準備 `app.env`

是的，`app.env` 放在主機上的這個資料夾：

```text
/home/ubuntu/gtalent_spring_boot_260801/app.env
```

它可以從目前 systemd 使用的 `.env` 複製：

```bash
cd /home/ubuntu/gtalent_spring_boot_260801
umask 077
cp .env app.env
chmod 600 app.env
nano app.env
```

保留原本的資料庫帳號、密碼、JWT、LINE、藍新等設定，並將 `DB_URL` 改成下面格式。`project26_v1` 如果不是你的資料庫名稱，請換成實際名稱：

```dotenv
DB_URL=jdbc:mysql://gtalent-mysql:3306/project26_v1?allowPublicKeyRetrieval=true&useSSL=false&serverTimezone=Asia/Taipei
```

`app.env` 每行使用 `KEY=value`。Compose 會原樣讀取值，請檢查引號和特殊字元是否為實際密碼的一部分。不要把 `app.env` 提交到 Git。原本的 `.env` 保留給 systemd，方便回復。

## 第五步：讓 Spring Boot 容器找到 MySQL

建立 Docker network，並讓既有 MySQL 容器加入：

```bash
docker network create gtalent-network
docker network connect --alias gtalent-mysql gtalent-network docker_mysql
```

如果網路已存在，略過第一行；如果容器已經加入，先檢查它是否有 `gtalent-mysql` 別名：

```bash
docker network inspect gtalent-network
```

MySQL 資料庫及帳號必須已建立，且帳號允許 Spring Boot 容器連線。這些命令不會建立或刪除 MySQL 資料。

## 第六步：放入 Compose 設定

在**自己的電腦**，於專案目錄執行，將 Compose 檔上傳至 EC2；請換成你的 SSH 金鑰路徑及 EC2 位址：

```bash
scp -i <SSH私鑰路徑> deploy/compose.yml ubuntu@<EC2主機>:/home/ubuntu/gtalent_spring_boot_260801/compose.yml
```

EC2 上的目錄結構如下：

```text
/home/ubuntu/gtalent_spring_boot_260801/
├── .env                 # 原本 systemd 使用，保留供回復
├── app.env              # Docker 使用，不提交 Git
├── compose.yml          # Spring Boot 容器設定
└── target/
    └── app.jar          # GitHub Actions 上傳的程式
```

## 第七步：啟動 Docker 服務

回到 **EC2** 執行：

```bash
cd /home/ubuntu/gtalent_spring_boot_260801
docker compose config --quiet
docker compose up -d
docker compose ps
docker compose logs --tail=100 app
```

等待程式啟動後檢查：

```bash
curl --fail http://127.0.0.1:8080/page/login -o /dev/null
```

再用瀏覽器確認網站登入及資料庫功能正常。Compose 將 8080 綁定在 `127.0.0.1`，適合原本的 Nginx 或反向代理也在同一台 EC2 的情況；若目前沒有反向代理，需先調整對外連線方式。確認 Docker daemon 已設定開機啟動。

## 第八步：啟用 GitHub Actions 自動部署

確認 Docker 網站運作正常、舊 systemd 服務已停止後，把本次修改提交、推送到 GitHub，恢復 GitHub Actions 的部署 workflow，並手動執行或透過 `main` 分支推送觸發。部署帳號需能讀取 `app.env`、寫入該目錄，並執行 Docker。

之後 GitHub Actions 會測試、產生 JAR、上傳 JAR 和 Compose 設定，並重新建立容器。若舊 systemd 服務仍在執行，或 EC2 尚未備妥 `app.env` 和 Compose 設定，部署會停止。

## 查看或重新啟動

```bash
cd /home/ubuntu/gtalent_spring_boot_260801
docker compose ps
docker compose logs --tail=100 app
docker compose restart app
```

修改 `app.env` 後，執行以下命令才會重新載入設定：

```bash
docker compose up -d --force-recreate
```

## 如果要回復原本的 systemd

先暫停 GitHub Actions 部署，再在 **EC2** 執行：

```bash
cd /home/ubuntu/gtalent_spring_boot_260801
docker compose down
sudo systemctl enable --now gtalent
sudo systemctl status gtalent --no-pager
```

回復前請確認原本的 `.env` 仍可連線資料庫；systemd 的 `127.0.0.1:3306` 與 Docker 的 `gtalent-mysql:3306` 不同。若新版已執行資料庫 migration，還需確認原版程式與目前資料庫相容。回復後不要啟用新的 Docker 部署 workflow。

## 關於 EC2 主機內建 MySQL

如果 EC2 除了 `docker_mysql` 還有安裝 Ubuntu 的 MySQL，請先確認沒有其他服務使用，並完成資料備份與遷移；確認容器資料庫的讀寫正常後，才停止或移除主機 MySQL。不要刪除 `docker_mysql` 或其資料 volume。
