# 忘記密碼流程

## 時序圖

```mermaid
sequenceDiagram
    participant User as 使用者
    participant Browser as 瀏覽器
    participant Server as 後端系統
    participant DB as 資料庫
    participant Mail as Email 服務

    User->>Browser: 點擊「忘記密碼」
    Browser->>User: 顯示輸入帳號或 Email 的畫面
    User->>Browser: 輸入帳號或 Email
    Browser->>Server: POST /members/forgot-password
    Server->>DB: 查詢會員是否存在

    alt 會員不存在
        Server-->>Browser: 回傳通用成功訊息
        Browser-->>User: 顯示「若帳號存在，將寄送重設密碼信」
    else 會員存在
        Server->>Server: 產生一次性重設密碼 token
        Server->>DB: 儲存 token hash、過期時間、使用狀態
        Server->>Mail: 寄送重設密碼連結
        Mail-->>User: 收到重設密碼 Email
        Server-->>Browser: 回傳通用成功訊息
        Browser-->>User: 顯示「若帳號存在，將寄送重設密碼信」
    end

    User->>Browser: 點擊 Email 中的重設密碼連結
    Browser->>Server: GET /page/reset-password?token=xxx
    Server->>DB: 驗證 token 是否存在、未過期、未使用

    alt token 無效或過期
        Server-->>Browser: 顯示連結無效或已過期
        Browser-->>User: 提示重新申請忘記密碼
    else token 有效
        Server-->>Browser: 顯示設定新密碼畫面
        User->>Browser: 輸入新密碼並送出
        Browser->>Server: POST /members/reset-password
        Server->>DB: 再次驗證 token
        Server->>Server: 密碼加密
        Server->>DB: 更新會員密碼
        Server->>DB: 標記 token 已使用
        Server-->>Browser: 回傳重設成功
        Browser-->>User: 導向登入頁或顯示成功訊息
    end
```

## 流程圖

```mermaid
flowchart TD
    A[使用者點擊忘記密碼] --> B[輸入帳號或 Email]
    B --> C[前端送出忘記密碼請求]
    C --> D[後端查詢會員]

    D --> E{會員是否存在?}
    E -- 否 --> F[回傳通用成功訊息]
    E -- 是 --> G[產生一次性重設密碼 token]

    G --> H[儲存 token hash、過期時間、未使用狀態]
    H --> I[寄送重設密碼 Email]
    I --> F
    F --> J[提示使用者檢查信箱]

    J --> K[使用者點擊 Email 連結]
    K --> L[後端驗證 token]
    L --> M{token 是否有效?}

    M -- 否 --> N[顯示連結無效或已過期]
    N --> O[請使用者重新申請忘記密碼]

    M -- 是 --> P[顯示設定新密碼畫面]
    P --> Q[使用者輸入新密碼]
    Q --> R[前端送出重設密碼請求]
    R --> S[後端再次驗證 token]
    S --> T{token 是否仍有效?}

    T -- 否 --> N
    T -- 是 --> U[加密新密碼]
    U --> V[更新會員密碼]
    V --> W[標記 token 已使用]
    W --> X[重設成功]
    X --> Y[導向登入頁]
```

## 補充說明

- 忘記密碼查詢會員時，不建議直接告訴使用者「帳號不存在」，避免被拿來測試哪些帳號已註冊。
- Email 內的 token 建議只顯示一次，資料庫只存 token hash，不直接存原始 token。
- token 應設定過期時間，例如 10 到 30 分鐘。
- 重設成功後，應把 token 標記為已使用，避免同一個連結被重複使用。
