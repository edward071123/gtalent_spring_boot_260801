# 專案部署到 Linux 步驟

日期：2026-09-03

專案：`gtalent_spring_boot_260801`

部署方式：使用 Spring Boot JAR + systemd 部署到 AWS Ubuntu 的 `/home/ubuntu` 底下。這個專案目前是 Maven 專案，Java 版本是 21，資料庫使用 MySQL，啟動時會透過 Flyway 自動建立/更新資料表。

---

## 1. Linux 主機先安裝必要套件

以下以 Ubuntu/Debian 為例。

```bash
sudo apt update
sudo apt install -y openjdk-21-jdk mysql-server nginx git
```

確認 Java 版本：

```bash
java -version
```

需要看到 Java 21。

---

## 2. 建立 MySQL 資料庫與帳號

進入 MySQL：

```bash
sudo mysql
```

建立正式資料庫與使用者：

```sql

CREATE USER 'admin'@'localhost' IDENTIFIED BY '請更換密碼';
  GRANT ALL PRIVILEGES ON *.* TO 'admin'@'localhost' WITH GRANT OPTION;

CREATE DATABASE project26_v1
    DEFAULT CHARACTER SET = 'utf8mb4';

CREATE USER 'project26_v1'@'%' IDENTIFIED BY '請更換密碼';
-- Grant select privilege to all databases;
GRANT SELECT, INSERT, UPDATE, DELETE, CREATE, ALTER, INDEX
    ON project26_v1.*
    TO 'project26_v1'@'%';

CREATE DATABASE project26_v1_test
    DEFAULT CHARACTER SET = 'utf8mb4';

CREATE USER 'project26_v1_test'@'%' IDENTIFIED BY '123123';
-- Grant select privilege to all databases;
GRANT SELECT, INSERT, UPDATE, DELETE, CREATE, ALTER, INDEX
    ON project26_v1_test.*
    TO 'project26_v1_test'@'%';
FLUSH PRIVILEGES;
EXIT;
```

注意：正式密碼不要放到 Git。

## 3. 把專案放到 Linux

AWS Ubuntu 建議先放在目前使用者的 home 底下，例如：

在/home/ubuntu下建立資料夾 gtalent_spring_boot_260801
```bash
mkdir gtalent_spring_boot_260801

```
gtalent_spring_boot_260801資料夾建立後把整個專案上傳到：

```text
/home/ubuntu/gtalent_spring_boot_260801
```

---

## 4. 建立正式環境 `.env`

專案會讀取根目錄的 `.env`：

```bash
cp .env.example .env
nano .env
```

正式機建議內容如下：

```properties
DB_NAME=project26_v1
DB_PORT=3306
DB_USERNAME=project26_v1
DB_PASSWORD=請換成正式密碼

TEST_DB_NAME=project26_v1_test
TEST_DB_PORT=3306
TEST_DB_USERNAME=project26_v1_test
TEST_DB_PASSWORD=

GMAIL_USERNAME=你的_gmail
GMAIL_PASSWORD=你的_gmail_app_password

JWT_SECRET=請換成至少32字元以上的隨機密鑰
JWT_ACCESS_TOKEN_SECONDS=900
JWT_REFRESH_TOKEN_SECONDS=604800

APP_BASE_URL=https://你的網域
PASSWORD_RESET_TOKEN_MINUTES=30
```

如果暫時沒有網域，可以先用：

```properties
APP_BASE_URL=http://伺服器IP:8080
```

## 5. 打包 Spring Boot JAR

在專案根目錄執行：

```bash
chmod +x mvnw
./mvnw clean package
```

如果測試資料庫還沒設定好，暫時可以先跳過測試打包：

```bash
chmod +x mvnw
./mvnw clean package -DskipTests
```

打包完成後，JAR 會在：

```text
target/gtalent_spring_boot_260801-0.0.1-SNAPSHOT.jar
```

---

## 6. 先手動啟動確認

```bash
java -jar target/gtalent_spring_boot_260801-0.0.1-SNAPSHOT.jar
```

確認沒有錯誤後，用瀏覽器或 curl 測：
(記得開aws防火牆)

```bash
curl http://你的ip:8080
```

第一次啟動時 Flyway 會自動執行：

```text
src/main/resources/db/migration
src/main/resources/db/seeder
```

如果資料表欄位不符合 Entity，因為專案設定是：

```properties
spring.jpa.hibernate.ddl-auto=validate
```

Spring Boot 會直接啟動失敗。這時要修 migration，不要手動亂改正式資料庫。

## 7. 建立 systemd 服務

建立服務檔：

```bash
sudo nano /etc/systemd/system/gtalent.service
```

內容：

```ini
[Unit]
Description=Gtalent Spring Boot App
After=network.target mysql.service

[Service]
User=ubuntu
Group=ubuntu
WorkingDirectory=/home/ubuntu/gtalent_spring_boot_260801
ExecStart=/usr/bin/java -jar /home/ubuntu/gtalent_spring_boot_260801/target/gtalent_spring_boot_260801-0.0.1-SNAPSHOT.jar
SuccessExitStatus=143
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

啟動服務：

```bash
sudo systemctl daemon-reload
sudo systemctl enable gtalent
sudo systemctl start gtalent
```

查看狀態：

```bash
sudo systemctl status gtalent
```

查看 log：

```bash
sudo journalctl -u gtalent -f
```

## 8. Nginx 反向代理

正式對外網址建議走 Nginx：

```text
使用者 -> https://你的網域/page/login -> Nginx 443 -> Spring Boot 127.0.0.1:8080
```

Spring Boot 本身維持跑在 `8080`，不用直接處理 HTTPS。


建立 Nginx 設定：

```bash
sudo nano /etc/nginx/sites-available/gtalent
```

如果你的正式網域是自己的 domain，例如 `example.com`，`server_name` 就填你的正式網域：


```nginx
server {
    listen 80;
    server_name example.com;

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

啟用設定：

```bash
sudo ln -s /etc/nginx/sites-available/gtalent /etc/nginx/sites-enabled/gtalent
sudo nginx -t
sudo systemctl reload nginx
```

測試 Nginx HTTP：

```bash
curl http://你的正式網域/page/login
```

## 9. 如果有網域，設定 HTTPS

如果你已經有正式網域，先確認 DNS A record 有指到 EC2 公網 IP：

```text
你的正式網域 -> 43.213.68.158
```

AWS Security Group 要開：

```text
HTTP   TCP 80   0.0.0.0/0
HTTPS  TCP 443  0.0.0.0/0
SSH    TCP 22   你的IP/32
```

正式情況下，`8080` 不需要對外開。Spring Boot 給 Nginx 從本機轉發即可。

安裝 Certbot：

```bash
sudo apt install -y certbot python3-certbot-nginx
```

申請憑證：

```bash
sudo certbot --nginx -d 你的網域
```

完成後，把 `.env` 的 `APP_BASE_URL` 改成：

```properties
APP_BASE_URL=https://你的網域
```

重啟服務：

```bash
sudo systemctl restart gtalent
```

最後用瀏覽器開：

```text
https://你的正式網域/page/login
```

不要開：

```text
https://你的正式網域:8080/page/login
```

## 11. 常見問題檢查

### 8080 被佔用

```bash
sudo lsof -i :8080
```

### MySQL 連不上

確認 MySQL 狀態：

```bash
sudo systemctl status mysql
```

確認 `.env`：

```bash
cat .env
```

確認可以登入：

```bash
mysql -u project26_v1 -p project26_v1
```

### Flyway migration 失敗

看服務 log：

```bash
sudo journalctl -u gtalent -n 200
```

重點看：

```text
Flyway
Migration
Hibernate validate
```

### Gmail 寄信失敗

Gmail 密碼通常要用 App Password，不是一般登入密碼。

`.env` 需要設定：

```properties
GMAIL_USERNAME=你的_gmail
GMAIL_PASSWORD=你的_gmail_app_password
```

## 14. HTTPS 憑證過期處理

如果 HTTPS 憑證是用 Certbot 申請的，通常會自動續期。可以先查看目前憑證狀態：

```bash
sudo certbot certificates
```

測試自動續期是否正常：

```bash
sudo certbot renew --dry-run
```

如果測試成功，代表之後憑證快過期時可以自動續期。

如果憑證已經快過期或已經過期，可以手動續期：

```bash
sudo certbot renew
```

續期完成後，重新載入 Nginx：

```bash
sudo systemctl reload nginx
```

檢查 Certbot 自動續期排程：

```bash
systemctl list-timers | grep certbot
```

如果沒有看到 certbot timer，可以啟用：

```bash
sudo systemctl enable --now certbot.timer
```

常見續期失敗原因：

- AWS Security Group 沒有開 `80`
- Nginx 沒有正常啟動
- DNS A record 沒有指到這台 EC2
- 網域換 IP 了
- Nginx 設定檔有錯

續期失敗時，先檢查：

```bash
sudo nginx -t
sudo systemctl status nginx
sudo certbot certificates
```
